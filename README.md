# Leader：AI 人物与动态技能实验

一个基于 Godot 4.6 的三维实验原型：模型扮演世界中的人物，选择做什么；程序负责空间移动、身体动作和世界规则。已有方法使用 Luau 技能，缺少方法时可以请求强模型编写，在独立场景验证后加载。

这是面向开发者的源码预览，不是完整生存游戏。当前主要验证四个人物的交互，不支持已经验证的500人社会模拟。模型输出、骨骼动作和长时间自主行为仍可能失败。

## 当前范围

- 第一人称洞穴与室外场景；键盘文字输入、可选语音输入和语音播放。
- 人物相对空间、个人感知、当天经历与主动回忆。
- 统一 Luau 技能调用、固定版本组合、取消、学习与修订。
- 拿取、松手、放置、生活物资操作的程序执行接口；有接口不代表全部场景均可靠。
- 强模型开发后端可选 Codex 或 OpenCode；默认未配置，不捆绑执行器、账号或额度。
- 拿取已验证从判断到实际持有；程序选择站位并协调IK，不在每个厘米级动作重新调用模型。

## 先离线查看

先按[安装与演示](GETTING_STARTED.md)获取模型资源包，再用Godot打开 `project.godot`。

无需模型账号的演示：

```powershell
& $env:LEADER_GODOT --path . -- --outdoor-preview
& $env:LEADER_GODOT --path . res://scenes/rig_lab.tscn
```

第一个入口查看场景，第二个是身体目标控制实验台。这两个演示不等于人物AI或动态技能编写已运行。完整人物交互需要另行配置本地执行服务及模型。

## 框架

玩家说话/输入文字 → 日常模型理解与选择技能 → Luau执行器请求世界操作 → Godot检查并执行 → 实际结果反馈。

缺少方法 → 强模型编辑独立技能工程 → 隔离场景执行与审查 → 验证通过的确切版本登记给人物。技能不能自行修改世界规则，不能通过台词直接改变库存或宣称目标完成。

## 已知限制

- 主要验证环境是Windows、Godot 4.6.2；WSL用于开发命令，不代表Linux原生游戏已验证。
- 持物仍是简化连接，没有完整手指物理、全身碰撞和动态平衡。
- 审查包含模型判断，不是代码与动作正确性的数学证明；隔离边界见架构说明。
- 长期记忆质量、完整世界恢复、多人物自主调度仍需完善。
- PC VR使用OpenXR；Quest 2通过PC连接测试，不提供Quest原生APK。
- 外部模型可能收费、限流或超时；语音、日常决策与技能开发分别配置，不提供共享账号或反代服务。
- 测试中的耗时只代表具体场景和机器，不承诺统一响应速度。

提交问题时请说明复现步骤、Godot版本、所选后端和脱敏后的错误。不要上传runtime目录、令牌、账户文件或完整个人对话。
